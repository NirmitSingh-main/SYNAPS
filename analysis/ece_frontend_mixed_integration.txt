3. MODIFICATIONS & RATIONALE
================================================================================
1. signal_processing/demodulation/qpsk.py:
   - Fixed Gray mapping implementation where (-I, +Q) mapped to [1, 0] instead of [0, 1]
     and (+I, -Q) mapped to [0, 1] instead of [1, 0], resolving a discrepancy with its
     own docstring, symbol_to_bits.py, and the dataset generator.
   - Restored 100.00% exact bit agreement on dataset QPSK reference signals.

2. backend/services/pipeline.py:
   - Added dynamic feature dimension slicing (`features[:, :self.model.input_features]`)
     to support loading models of any feature dimensionality (4-feature baseline or 6-feature).
   - Added metadata resolution for MIXED vs SINGLE signals.
   - For MIXED signals: composite waveform is preserved intact; single-bitstream demodulation
     is bypassed; synchronization status set to "MIXED_COMPOSITE"; per-component metadata
     extracted; validation status explicitly set to "Component bit recovery not validated".
   - For Pure signals: recovered bits are compared against metadata reference bits to calculate
     exact matched bits, bit accuracy %, BER, and validation status (VALIDATED / SUBOPTIMAL).
   - Enhanced frontend_data payload with `signalType`, `detectedComponents`, `componentResults`,
     and `bitRecovery` structures.

3. backend/schemas/response.py:
   - Extended Pydantic schemas (`ModulationPrediction`, `BitRecoverySummary`,
     `IntelligenceReportResponse`) to support `signal_type`, `detected_components`,
     `bit_recovery`, and `component_results`.

4. backend/api/signal.py:
   - Updated `list_sample_signals` to use canonical dataset directory getters
     (`get_class_iq_dir`, `get_class_wav_dir`) matching the v2 dataset layout.

5. intelligence/report/report.py:
   - Updated report generator and text formatter to include `signal_type`, `detected_components`,
     and structured `bit_recovery` validation tables.

6. frontend/SNAPS-FE/src/data/demoData.ts & frontend/SNAPS-FE/src/services/api.ts:
   - Extended `DemoAnalysis` and `AnalysisResponse` TypeScript interfaces with `signalType`,
     `detectedComponents`, `componentResults`, and `bitRecovery` fields.

7. frontend/SNAPS-FE/src/components/ClassificationCard.tsx:
   - Enhanced card to display multi-carrier tag and component list (e.g. "BPSK + QPSK")
     when analyzing MIXED signals.

8. frontend/SNAPS-FE/src/pages/ResultsPage.tsx:
   - Added dedicated Bit Recovery & Component Analysis section.
   - For Pure signals: displays 4-column metric grid (Reference Bits, Recovered Bits,
     Bit Accuracy %, BER).
   - For MIXED signals: displays component table (Component #, Modulation, Symbol Rate,
     Frequency Offset, Frequency Placement, Status) with explicit non-validated disclaimer.

9. tests/test_pipeline.py:
   - Extended test suite to cover all 4 pure classes (BPSK, QPSK, FSK, QAM16), 2-component MIXED,
     3-component MIXED, and FastAPI Pydantic schema validation.
